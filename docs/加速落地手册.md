## 为什么大陆加速不走 Cloudflare

Cloudflare 免费 / Pro 计划在中国大陆**没有节点**。大陆流量会被 anycast 绕到香港、新加坡或洛杉矶。
这不是推测——Supabase 边缘日志里已经能看到这条绕路：

```
colo  请求数   平均 origin_time   峰值
HKG     194        249.8 ms      1202 ms
LAX     105        438.7 ms      1311 ms   ← 大陆用户被绕到洛杉矶
SIN      79        236.9 ms       798 ms
```

大陆节点（Cloudflare 中国网络）需要 **Enterprise 计划 + 京东云合作**，不是免费版能开的能力。

所以分工是：

- **大陆线路** → 国内 CDN（有备案才能用大陆节点，这是备案最大的价值）
- **境外线路** → Vercel 直连，或按需接 Cloudflare（缓存规则 / WAF / 分析）
- **Cloudflare MCP** → 管账号、查观测、读文档；不承担大陆加速

## 目标架构

```
                       ┌── 国内线路 ──→ 阿里云 CDN/全站加速 ──回源──┐
用户 ──→ myquiz.cn ────┤                                              ├──→ Vercel hkg1
                       └── 境外线路 ──→ Vercel（直连）                │      （源站）
                                                                      │
         media.myquiz.cn ──（本次未启用，见「媒体」一节）─────────────┘
```

## 步骤

### 1. 开通加速产品

需要的是**对动态请求也做优化**的产品（阿里云「全站加速 DCDN」，现多归入「边缘安全加速 ESA」），
而不是纯静态 CDN——本站每个页面都是 SSR，纯 CDN 只能缓存静态资源，对首字节没有帮助。

> 购买前在控制台确认当前的产品命名与计费方式（按流量 / 按带宽），本文不锁定具体 SKU。

### 2. 添加加速域名

- 加速域名：`www.myquiz.cn`（建议先用子域，验证通过再切主域 `myquiz.cn`）
- 源站类型：**域名**
- 源站地址：Vercel 分配的 CNAME（`cname.vercel-dns.com`），或直接填上面两个 anycast IP
- **回源 HOST：必须填 `myquiz.cn`**。Vercel 靠 Host 头路由到对应项目，填错会回源到 404
- 回源端口 / 协议：443 / HTTPS
- 证书：在 CDN 侧申请或上传 `myquiz.cn` 的证书

### 3. 缓存规则（这一步最容易出事，逐条照做）

| 路径 | 缓存策略 | 理由 |
|---|---|---|
| `/_next/static/*` | 缓存 1 年，**忽略参数** | 文件名带内容哈希，天然不可变 |
| `/api/*` | **不缓存** | OSS 签名是即时计算且含时效 |
| 其他全部（HTML / RSC） | **不缓存** | 见下 |

**不要缓存 HTML，一条都不要。** 两个独立原因：

1. **串号**：本站每个页面都是按登录用户渲染的（`cookies()` + 逐页 `requireUser()`）。
   缓存 HTML 会把 A 用户的页面发给 B 用户——这是安全问题，不只是显示问题。
2. **RSC 预取会坏**：Next 的客户端导航靠 `_rsc` 查询参数区分「HTML」与「RSC 载荷」，
   并依赖 `Vary: rsc, next-router-prefetch, ...` 等响应头。多数 CDN 不认 `Vary`，
   只按 URL 缓存——`_rsc` 一旦不在缓存键里就会互相污染，表现为偶发 307 跳转或页面错乱。

配套设置：**缓存键必须"不忽略参数"**（阿里云默认忽略查询串，要手动改成保留全部参数）。
就算暂时不缓存 HTML，也建议先改掉，避免后续误开缓存时踩坑。

### 4. 云解析分线路

在云解析 DNS 里为 `www` 与 `@` 各加两条记录：

| 线路 | 记录类型 | 值 |
|---|---|---|
| 默认（大陆） | CNAME | CDN 分配的加速域名 |
| 境外 | CNAME | `cname.vercel-dns.com`（保持现状的等价写法） |

> 阿里云云解析免费版支持「默认 + 境外」两档线路；按运营商（电信/联通/移动）细分需要付费版。
> 对本站来说两档够用——分运营商主要服务于多源站容灾场景，这里只有一个源站。

### 5. 验证

```bash
# 大陆节点应解析到 CDN
nslookup www.myquiz.cn 223.5.5.5      # 阿里 DNS
# 境外节点应解析到 Vercel
nslookup www.myquiz.cn 8.8.8.8        # Google DNS

# 静态资源应命中 CDN 且有长缓存
curl -sI https://www.myquiz.cn/_next/static/<任一构建产物>
#   期望：Cache-Control 带 max-age=31536000, immutable；响应头能看到 CDN 厂商头

# 登录态页面必须回源、不可被 CDN 缓存
curl -sI https://www.myquiz.cn/dashboard
#   期望：无 CDN 命中标记（X-Cache: MISS 之类），且每次内容随登录态变化
```

最后**用浏览器完整走一遍**：登录 → 侧栏切换 → 题库筛选 → 审核详情。
RSC 缓存键配错的表现是"点了没反应/偶发跳登录页"，只有真实导航能暴露。

## 媒体（图片 / 视频）——本次只做了压缩，未换域名

已落地：所有图片走 OSS 图片处理，在 OSS 侧缩到展示尺寸再回源。实测：

| 场景 | 原图 | 处理后 |
|---|---|---|
| 题干插图（内联，w_720 + webp） | 7,611,278 B | **38,716 B**（约 1/197） |
| 题干插图（全屏，w_1600 + webp） | 7,611,278 B | 137,694 B |
| 头像（w_96 + webp） | 137,565 B | **1,978 B** |

体积问题已经解决。**若之后仍嫌慢**（首字节而非体积），再考虑给 OSS 挂国内 CDN：

- 用 `media.myquiz.cn` 这类**备案主域的子域**做 CDN 域名（证书与备案一道走，比另找域名省事）
- 源站填 OSS 的 bucket 域名，回源 HOST 与 bucket 一致
- 图片处理参数（`x-oss-process`）会随 URL 一起进 CDN 缓存键，不需要额外配置
- 切换只需改一个环境变量：`NEXT_PUBLIC_OSS_PUBLIC_HOST`（库里只存 key，不存完整 URL，所以全局生效）；
  Flutter 端同步改 `mianyang_quiz/config/*.json` 的 `OSS_PUBLIC_HOST`

`.env.local` 里已经写好但**未启用**的 CNAME（`mianyang-question-bank.cn-chengdu.taihangztn.cn`）
需要在 OSS「域名管理」绑定 HTTPS 证书才能用；那个域名的备案情况未知，走 `media.myquiz.cn` 更稳。

## 流式渲染（白屏）——已完成

原先每个页面的第一件事都是 `await requireUser()` / `await searchParams`，全站又没有任何
`<Suspense>` 边界，React 只能一路往上找边界，找不到就整棵子树一起等：**第一字节 = 最慢查询的时间**。

改动：

| 文件 | 作用 |
|---|---|
| `app/(app)/loading.jsx` | 给每个 `(app)` 页面套一层边界：外壳先出，页面骨架顶上 |
| `app/(auth)/loading.jsx` | 同上，覆盖注册页（它要查一次启用学校列表才渲染表单） |
| `app/(app)/layout.jsx` | 不再在渲染 shell 之前等网络：闸门改用 `requireSession()`（本地验签），档案/学校名/反馈角标整块推进 `<Suspense>`（侧栏骨架先占位） |
| `lib/auth.js` | 拆出 `getSessionClaims()` 与 `requireSession()`；判定条件与 `requireUser()` 一致，谁被踢去登录页没有变化 |
| `app/(app)/dashboard/page.jsx` | 四张统计卡 + 学校贡献 + 最近入库 + 我的进行中，各自一个 `<Suspense>` 与各自的缓存 loader（「我的题目」与「我的进行中」共用 `getMyRows()`，只打一次） |

实测（`next start`，本机直连海外 Supabase）：

```
/register 改前：TTFB ≈ 3.3s（白屏直到查完）      ← 由"直接查 Supabase 1.6–2.7s"推算
/register 改后：TTFB = 24ms，内容 +2.9s 到达
流式分块实测：
  chunk 0  +1ms     18391B  SKELETON + SUSPENSE-PLACEHOLDER
  chunk 1  +2865ms   3909B  REAL-CONTENT
  chunk 2  +2876ms  12826B  REAL-CONTENT
```

> ⚠ **别写 `.tsx`**。本仓库是纯 JS 工程（`jsconfig.json` + `components.json` 的 `"tsx": false`）。
> 一旦出现 `.tsx`，Next 会自动生成一个**不带 `paths` 映射**的 `tsconfig.json`，而 tsconfig 优先级
> 高于 jsconfig —— 结果全站 `@/…` 别名解析全部失败（实测 158 个报错，且报的是"找不到 components/xxx"
> 这种极具误导性的错）。骨架文件一律 `.jsx`。
