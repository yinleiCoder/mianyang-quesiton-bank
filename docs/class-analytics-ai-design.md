# 班级学情 + AI 分析：目标与待定口径

> 2026-10-05 起的这一轮需求。**先写下来再开工** —— 理由同 `pending-design.md`：
> 这些口径是逐条问出来的，只留在对话里就会丢，下次带着全新上下文要重新问一遍。
>
> 状态：**第 1、2、3 步已上线**（0086 全省 / 0087 班级考试结果 / 0088 AI 分析），
> **第 4 步（"复习任务"）用户明确不做**（2026-10-08）—— 这一轮到此结束。
> 下面把「查证过的事实」与「待定」分开写。

## 一、需求原话（拆成四块）

> nextjs 关注班级学情，尤其是考试卷结果，我需要展示班级学情进行分析，最高分是谁，最低分是谁等等，
> 全班、全市、**全省**的排名（flutter 也需要加入全省的排名）。
> AI 帮助我分析整套试卷的情况以及学生的知识点掌握做题情况（学科系统规划复习内容，紧扣近期复习进度，
> 聚焦重要知识点、高频考点、易错短板等开展知识巩固、适度拓展和能力提升训练，精准对接学情和阶段复习需求，
> 真正服务备考、助力提分），图表文字的形式让我更好了解我的学生。

拆开就是四件事：

1. **班级学情（网页端）**：最高分/最低分是谁、分布、名次 —— 教师一眼看懂这个班
2. **全省排名**：现有榜单加一档「全省」（**网页端与 Flutter 都要**）
3. **AI 分析整套试卷 + 学生的知识点掌握**：输出"复习规划"式的文字（重点/高频/易错/拓展）
4. **图表 + 文字**：上面三块都要可视化，不是一堆数字

## 二、查证过的事实（2026-10-05）

- **榜单已经有三档**：`paper_leaderboard(p_paper_id, p_scope, p_class_id, p_limit)`，
  scope 由 `resolve_paper_scope` 解析 —— **它的白名单写死为 `class / school / city`，
  传别的直接 raise「榜单范围不合法」**。所以"加一档全省"= 扩白名单 + 一个返回分支，
  不是重写排序逻辑。
  （**0086 已加第四档 `province`**；这一条是当时查到的事实，现状见第五节。
  另外当时没看出来的：city 档实际是"全平台"，因为 0077 写的时候 schools 还没有城市列。）
- **试卷逐题统计已经很厚**：`paper_question_stats`（0078）每题给 `total/blank/graded/correct/
  correct_rate/pending/options（含谁选了什么）/text_counts/wrong_students/wrong_total` ——
  **错答名单、选项分布、填空频次都有**，AI 分析和图表都不缺数据源。
- **班级学情已有一版**：`class_learning_report`（0079）+ 网页 `components/classes/*`
  （weakness-panel「最该讲的题」、alerts-panel 成绩下滑、participation、student-table）。
  **"最高分是谁/最低分是谁"这一层还没有**（现有的是聚合与高危题）。
- **知识点掌握**：`my_node_accuracy`（0080，个人视角）、`class_learning_report` 里的
  `node_accuracy`（班级视角）；两端各有 `rollUpByTopNode` 上卷到顶层科目。
- **AI 已经接好**：`lib/deepseek.js` + `lib/use-deepseek-prefs.js`（教师可自选模型/参数）。
  ~~API key 走服务端~~ —— **这一句当时记错了**（2026-10-08 做第 3 步时核实）：现有 AI 是
  **教师自带密钥、浏览器直连 DeepSeek**，`lib/deepseek.js` 的头注写着"本模块不读 process.env，
  也没有任何服务端调用路径"，密钥只存教师本机 localStorage —— 所以站点不承担任何 AI 费用。
  第 3 步沿用了这条路（见第七节）。

## 三、口径（2026-10-05 用户逐条拍板）

| # | 问题 | 定论 |
|---|---|---|
| A | "全省"算哪些人 | **全省考过这份卷的人都算**（与现有全校/全市同一口径，不按年级/专业过滤） |
| B | 全省榜的可见性 | **实名，与现有口径一致**（学生看自己 + 前三；教师看全量）。理由：同一份正式卷的同类比较，且 city 档已经是这么做的 |
| C | AI 分析的粒度与触发 | **按「卷 + 班」生成一次、缓存**：教师点一下生成，结果存库全班共用；数据不变就不重算（按"卷面 + 该班成绩"的指纹判断） |
| D | 喂给模型的数据 | **聚合 + 逐题，不带学生姓名**：卷面、逐题正确率、选项分布、填空频次、高危题清单都给；错答名单只给"第 N 人"这种编号 |
| E | "紧扣近期复习进度"从哪来 | 库里**没有"复习进度"这个概念** → 生成时由教师填一句（如"这周复习到 Excel 函数"），**可选**；不填就按最近 N 天的练习记录推。这一条是设计者建议，用户未明确表态，可改 |

## 五、落地记录：第 1 步（0086，2026-10-05）

**"纯增量"这个判断是错的，实际动了 city 的口径**：0077 写的时候 `schools` 还没有城市列，
所以「全市」档实际是**全平台**（0077 的注释就写着"全市 = 全平台"）。0082 加了
`schools.city_id` 之后这个标签已经失真，而如果只加一档同样不筛的「全省」，两个页签的
数字会一模一样。用户 2026-10-05 拍板：**「全市」改成真按市筛**（人的市由 profile → school
→ city 推导，0082 的规矩），**「全省」才是不筛的那一档**。

落地范围：

- `0086_province_leaderboard.sql`：`resolve_paper_scope` 白名单加 `province`、city 分支收口到市；
  `paper_leaderboard` 四档分区（省不分区 / 市按 `schools.city_id` / 校 / 班）+ viewer 加
  `province_rank/total`；`paper_question_stats` 的三处范围筛选跟着走（口径只有一份）。
- 网页端：`lib/analytics.js` 的 `SCOPE_KEYS/LABELS` + 我的位置卡加全省；Flutter：枚举加
  `province`、viewer 加两字段、我的位置卡加全省。
- **新增 `no_school` 这个 viewer_note**：线上有 3 个没绑学校的学生，原先「全市」能看到全平台，
  收口后会看到一张空榜 —— 必须说明白"先看全省"，否则等于告诉他们成绩丢了。

今天只有一个市（绵阳市，10 所学校全挂着），所以**数字一个都没变**；差别要到接入第二个市的
当天才出现，那时「全市」才不会串市。**注意**：平台自己的「市级题库（平台）」这所学校也挂着
绵阳市，所以系统管理员的"我的市"是绵阳 —— 这正是 0082 留给第 2 步的那个问题
（非实体学校怎么算市），本轮**刻意没动**。

## 六、落地记录：第 2 步（0087，2026-10-05）

班级学情页（`/classes/[id]`）多了**考试结果**面板，放在最前面。三条口径也是当场拍板的：

| # | 问题 | 定论 |
|---|---|---|
| A | 形态 | **每份卷一张卡片**（参与人数、班均、最高/最低/进步最大、分数段分布、去榜单/讲评的链接），不是"只做最近一场" |
| B | 进步最大 | **同一学生在这份卷与上一份卷之间的得分率差**（两场都已出分；中间缺考的不参与） |
| C | 列哪些卷 | **跟随页面的 7/30/90 天窗口**，与同一页其它面板同口径 |

- `0087_class_exam_results.sql`：一条新 RPC（**没有动 0079** —— 那条是练习口径，
  改它等于把两种口径搅在一起）。只算官方成绩 + 当前入库版本 + 学生逐行过 `can_view_student`
  （与同页参与度面板同一个分母）。
- 网页端：`components/classes/exam-results-panel.jsx` + `loadClassExamResults`。
- **上线时抓到的一个真 bug**：卷序 `ord=1` 是**最新**那份，所以"上一场"是 `ord + 1`；
  先写成了 `ord - 1`，合成数据一跑就把进步榜算成了"这份卷比更早那份"。已修 + 用两卷合成
  场景回归过（老卷不再有"进步"、新卷的进步落在对的人身上）。
- 顺带给讲评页加了个 `?class=`（原先只认自己名下第一个班）：从某个班的成绩点"讲评"，
  投出来要是另一个班就荒唐了。

**仍然没有"布置考试"**，所以每张卡片的"参加 X/Y 人"是常态而非异常 —— 这一条不解决，
"全班考试学情"永远只是"本班考过这份卷的人"。第 3 步（AI 分析）会原样继承这个前提。

## 七、落地记录：第 3 步（0088，2026-10-08）

独立页 `/classes/<id>/ai/<paperId>`：成绩概览（复用第 2 步的分布条）+ AI 报告 + 生成按钮。

**开工前先纠正了设计稿的一处事实错误**（见第二节）：现有 AI 是教师自带密钥、浏览器直连，
没有服务端密钥。用户 2026-10-08 拍板**沿用这条路**（站点不出钱、不碰密钥），报告生成后存库、
全班共用 —— 生成者只花一次钱。

| # | 问题 | 定论 |
|---|---|---|
| A | 谁付钱 | **教师自带密钥**（与导入解析同一条路）；站点不提供公共密钥 |
| B | 放哪里 | **独立页**（能发到教研群；报告六七段，塞进班级看板的卡片会把那页拉垮） |

落地要点：

- `0088_class_ai_report.sql`：`class_ai_reports` 表（**按"卷面 + 班"唯一**，重算即覆盖）+
  一条内部函数 `_class_ai_data`（喂模型的那份数据 = 指纹的唯一真源）+ 三条 RPC
  （读报告 / 取 payload / 存结果）。表**一条 RLS 策略都没有**：判据 `can_view_class` 已经
  revoke from authenticated，策略里根本调不到它 —— 读写全走 definer，权限推理只有一份。
- **指纹 = md5(喂给模型的那份 jsonb)**。存的时候客户端必须把服务端给的指纹原样带回来，
  对不上就拒收（40001）：生成期间又有人交卷/判分的话，这份结论对应的已经不是现在的学情了。
  页面据此提示"重新生成"，而不是把旧结论当新的用。
- **匿名**：payload 里没有姓名，错答名单是"学生1、学生2"（按姓名序编号，稳定）。要认人就去
  「试题分析」页（那里本来就实名）。题目**带知识点名**（questions.course_node_id → subject_nodes），
  否则"重点/易错知识点"无从谈起。
- 提示词在 `lib/ai-report-prompt.js`：SYSTEM_PROMPT 逐字节稳定（前缀缓存），数据与"近期复习进度"
  进 user 消息。**明确要求模型沿用编号、不许猜姓名**。返回必须是 json（callChat 本就开 JSON Output），
  校验不过就不入库（宁可让教师重试，也不存半截报告）。
- 密钥面板（`components/import/deepseek-settings-panel.jsx`）加了 `purpose` 参数：分析场景下
  "一份 200 页的卷子约 ¥1~2"和"不支持图片会解析失败"都是错的，换成分析口径的文案。

**口径 E 的另一半也补上了（同日）**：payload 里多了 `practice`（本班最近 30 天的练习，
按最弱的知识点排序，**至少 3 次作答**才算数、只给最弱的 8 个）。教师没填复习进度时，
提示词让模型据此推断教学进度——练到过的说明教过了（其中最弱的就是这次要补的），
没出现的说明还没到。用真模型验过：报告里确实引用了"近 30 天练习正确率 61.07%（917 次）"，
巩固项也落在"已练过且最弱"的那个知识点上。

**验证**（2026-10-08）：
- `npm run test:ai-report`：11 项纯函数断言（拼消息、校验、`arr` 兜底）。
- `scripts/test-ai-report-live.mjs`：**用真 DeepSeek 跑通一次**（16s，1449+3285 tokens）——
  报告全程只用"学生N"、引用了练习数据、分清了"6 人参加 / 27 人班级"（明说 21 人不能按这次成绩判定），
  结构与 `validateAiReport` 的要求一致。跑之前逐项核对过喂进去的数据与库里一致。
- 没验的：浏览器里点"生成"那一下（本机 e2e 的 Chrome 配置里没有登录会话）。
  中间那一段（取 payload → 调模型 → 存库）两条腿都验过，接缝处只有一次点击的距离。

**两个渲染 fixture**（`app/dev-exam-panel`、`app/dev-ai-report`）：只渲染写死的假数据，
用来检查排版与空态；线上按 `VERCEL_ENV` 直接 404，本地与 preview 照常可用。
**删之前先问**（用户 2026-10-08 的要求，同样的话也写在文件头与 scripts/e2e-cdp.mjs 里）。

**入口返工（2026-10-08，上线当天）**：第一版只把入口挂在班级学情页的考试卡片上，
用户反馈"并没有看到 AI 分析"——那条路要先想到"去班级看"，实际找不到。补了一个：
**试卷成绩页 `/papers/<id>/board` 选了班级时，右侧出现「让 AI 分析这个班」**（教师可见，
学生不给）。看完成绩单最自然的下一步就是让 AI 说说这个班，入口就该在那儿。
教训记在这里：**功能做完了不等于能被找到**，尤其当入口只挂在一个次要页面的子元素上时。
